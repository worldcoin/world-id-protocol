## 1. Abstract

This spec defines three circuit components that World ID proofs share: **World ID Authentication**, **Credential Verification** and **Session Commitment**. Each is specified once, with its inputs and constraints, and is embedded by reference in other circuits, as [WIP-106][wip-106] does for Authenticator Assertions.

## 2. Motivation

The same logic is specified several times today: World ID authentication in the Query and Uniqueness Proofs, [WIP-103][wip-103] and [WIP-202][wip-202]; Credential verification in the Query Proof and WIP-202; the session commitment in the Uniqueness Proof and WIP-202. Each copy can drift, and every new circuit adds another. Specifying each component once, with one reference library per component, keeps them consistent and lets new circuits reuse them.

## 3. Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [RFC 2119](https://www.ietf.org/rfc/rfc2119.txt).

1. The terms World ID, [Authenticator](https://docs.rs/world-id-core/latest/world_id_core/struct.Authenticator.html), Issuer and [Credential][credential] are as defined in the World ID Protocol.
2. The Field ($F$), the Curve (`BabyJubJub`), the hashes ($H_t$), EdDSA, `PublicKey` and Merkle inclusion MUST follow [WIP-100][wip-100].
3. A component introduces the inputs listed for it. An embedding circuit MUST expose the **Public** inputs as its public inputs and keep the others private.

### 3.2 World ID Authentication

Proves that a registered Authenticator key of a World ID signed `message`, and returns that World ID's `leaf_index`.

| Input | Visibility | Type | Description |
| --- | --- | --- | --- |
| `merkle_root` | **Public** | Field element | Root of the `WorldIDRegistry`. |
| `message` | Set by the embedding circuit | Field element | The message the Authenticator signs. |
| `user_pk` | Private | [`PublicKey`; `NUM_KEYS`] | The World ID's registered Authenticator keys, in `WorldIDRegistry` slot order. |
| `pk_index` | Private | Field element | Index of the signing key in `user_pk`. |
| `leaf_index`, `siblings` | Private | Field element, [Field element; 30] | The World ID's position in the `WorldIDRegistry`. |
| `sig_r`, `sig_s` | Private | [Field element; 2], Field element | The Authenticator's signature. |

The component MUST enforce:

1. **Key selection.** One of the World ID's registered Authenticator keys signed `message`.
   - Range-check `pk_index` as 3-bit and constrain `pk_index < NUM_KEYS`.
   - Select `pk = user_pk[pk_index]`. Inactive slots are the identity $(0,1)$, which WIP-100 signature verification rejects.
2. **Registry inclusion.** The key set is registered for a World ID in the `WorldIDRegistry`.
   - Compute `H_16(MERKLE_LEAF_DS; user_pk[0].x, user_pk[0].y, …, user_pk[6].x, user_pk[6].y)`, including inactive slots.
   - Prove its inclusion at `leaf_index` under `merkle_root`, per WIP-100.
3. **Signature.** The selected key signed `message`.
   - Verify `(sig_r, sig_s)` by `pk` over `message`, per WIP-100.

### 3.3 Credential Verification

Proves that an Issuer issued a Credential to a World ID that is valid at `now`, and returns its `claims`.

| Input | Visibility | Type | Description |
| --- | --- | --- | --- |
| `cred_pk` | **Public** | `PublicKey` | The Issuer's key. |
| `issuer_schema_id`, `issuer_version` | **Public** | Field element | Credential type and schema version. |
| `genesis_issued_at_min` | **Public** | Field element | Minimum time the Credential was first issued. |
| `now`, `leaf_index` | Set by the embedding circuit | Field element | Current time, and the World ID from [World ID Authentication](#32-world-id-authentication). |
| `claims` | Private | [Field element; `MAX_CLAIMS`] | Credential claims. |
| `cred_associated_data_hash`, `cred_genesis_issued_at`, `cred_expires_at`, `cred_sub_blinding_factor`, `cred_id` | Private | Field element | Remaining Credential fields covered by the Issuer signature. |
| `cred_r`, `cred_s` | Private | [Field element; 2], Field element | The Issuer's Credential signature. |

The component MUST enforce:

1. **Credential signature.** The Issuer issued the Credential to this World ID.
   - Compute `sub = H_3(DS_CREDENTIAL_SUB; leaf_index, cred_sub_blinding_factor)`.
   - Compute `claims_hash`, the Poseidon2 $t=16$ permutation over `[claims[0], …, claims[14], 0]` with output element `1`.
   - Range-check `cred_id` as 64-bit and `issuer_version` as 8-bit, and compute `cred_id_packed = cred_id + issuer_version * 2^64`.
   - Verify `(cred_r, cred_s)` by `cred_pk` over `H_8(DS_CREDENTIAL_V1; issuer_schema_id, sub, cred_genesis_issued_at, cred_expires_at, claims_hash, cred_associated_data_hash, cred_id_packed)`, per WIP-100.
2. **Credential validity.** The Credential is valid at `now` and meets the minimum first-issuance time.
   - Range-check `now` as 32-bit and the Credential times as 64-bit.
   - `now < cred_expires_at` and `genesis_issued_at_min <= cred_genesis_issued_at`.

### 3.4 Session Commitment

Proves that `session_id`, if set, identifies a World ID.

| Input | Visibility | Type | Description |
| --- | --- | --- | --- |
| `session_id` | **Public** | Field element | Session commitment, or `0`. |
| `leaf_index` | Set by the embedding circuit | Field element | The World ID from [World ID Authentication](#32-world-id-authentication). |
| `session_id_r` | Private | Field element | Blinding factor of the session commitment. |

The component MUST enforce:

1. **Session commitment.** `session_id` is `0` or the World ID's commitment.
   - `session_id * (session_id - H_3(DS_SESSION_COMMITMENT; leaf_index, session_id_r)) == 0`.

### 3.5 Composition

1. An embedding circuit MUST pass the `leaf_index` returned by [World ID Authentication](#32-world-id-authentication) to every other component, as the same witness. Otherwise it proves only that the prover controls some World ID, not the one the Credential or session concerns.
2. The embedding circuit MUST compute `message` with its own domain separator, so a signature for one circuit can not be replayed in another.

### 3.6 Reference Verification

An RP accepts the components' public inputs if:

1. `merkle_root` is a root the `WorldIDRegistry` accepts.
2. `cred_pk` is a trusted Issuer key for `issuer_schema_id` and `issuer_version`, and `genesis_issued_at_min` and `now` meet the RP's policy.
3. If the RP needs a proof to concern the same World ID as another proof, `session_id` is nonzero and equals that proof's session commitment.

## 4. Rationale

1. **Components embedded by reference.** As with [WIP-106][wip-106] §3.7 and [WIP-201][wip-201] §3.9, a component is specified once and each circuit states only what it adds.
2. **`message` from the embedding circuit.** Authentication only proves that a registered key signed something; what it signs, and why, is the embedding circuit's statement.
3. **Fixed tree depth.** The component follows WIP-100's 30-level `WorldIDRegistry` tree, so no circuit takes the depth as an input.

## 5. Security

1. **Leaf-index binding.** Without the shared `leaf_index` of [Composition](#35-composition), a proof can combine one World ID's Authenticator with another World ID's Credential.
2. **Message separation.** Two circuits that sign the same `message` format accept each other's signatures. Distinct domain separators prevent this.

## 6. Backwards Compatibility

This WIP introduces no new behavior. The Query and Uniqueness Proofs, [WIP-103][wip-103] and [WIP-202][wip-202] specify the same logic in their own terms; they can adopt these components without changing their outputs, except that WIP-103's public `depth` input is fixed to 30.
