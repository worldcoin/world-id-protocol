## 1. Abstract

The **DeepFace Proof** is a ZK circuit. It proves to a Relying Party (RP) that:

- a [WIP-110][wip-110] Verifier compared the Orb credential image of the prover's World ID with a live capture, and optionally with the RP's challenge image, and accepted at the RP's assurance level;
- the request the Verifier compared came from a genuine Authenticator ([WIP-106][wip-106]) acting for that World ID.

No image, embedding or score is revealed.

## 2. Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [RFC 2119](https://www.ietf.org/rfc/rfc2119.txt).

Field, curve, hashing and `BabyJubJub-EdDSA-Poseidon2` follow [WIP-100][wip-100].

### 2.1 Request layout

The circuit accepts only [WIP-110][wip-110] `method`s with this `compare` layout:

| Position | Entry |
| --- | --- |
| `compare[0]` | Orb credential thumbnail (`thumbnail.png` of the PCP) |
| `compare[1]` | Live capture frame |
| `compare[2]` | RP challenge image, absent in the 2-way flow |

### 2.2 Constants

| Constant | Value | Description |
| --- | --- | --- |
| `DS_WIP_111` | `127603488023523044162070750169730678246161835968334` (`b"WORLD-ID/WIP-111/SIGN"`) | Authenticator authorization message. |
| `CLAIM_INDEX` | `0` | Credential claim holding the PCP `hashes.json` commitment. |

### 2.3 Inputs

The circuit has no outputs; a valid proof means every constraint in [§2.4](#24-what-the-circuit-verifies) holds for the public inputs.

**Public**

| Input | Description |
| --- | --- |

| `method` | Accepted [WIP-110][wip-110] method. |
| `assurance_level_min` | Minimum accepted assurance level. |
| `comparison_age_max` | Maximum age of the comparison, in seconds. |
| `challenge_hash` | `R(SHA-256(challenge image))` as in [WIP-110][wip-110], or `0` for the 2-way flow. |
| `now` | Current time, in seconds since the Unix epoch. |
| `trust_anchor_key`, `aud`, `nonce`, `platform`, `sec_level`, `sec_meta` | [WIP-106][wip-106] AAT verification inputs. |
| `merkle_root` | `WorldIDRegistry` root. |
| `issuer_schema_id`, `cred_pk` | Credential type and Issuer key. |
| `genesis_issued_at_min` | Minimum credential genesis issuance time. |
| `session_id` | Session commitment, or `0`. |

**Private**

| Input | Description |
| --- | --- |
| `iat`, `token_method`, `assurance_level`, `request_hash`, `compared_entry_hash_0..3`, `token_sig` | [WIP-110][wip-110] token claims and signature. |
| `exp`, `sec_flags`, `aat_sig`, `blind` | [WIP-106][wip-106] AAT values. |
| `hashes_json`, `hashes_json_len`, `thumbnail_offset` | The PCP `hashes.json` bytes, their length, and the offset of the `"thumbnail.png":"<hex>"` entry. |

| `user_pk`, `pk_index`, `auth_sig` | Registered Authenticator keys, the key used, and its signature. |
| `leaf_index`, `siblings` | `WorldIDRegistry` inclusion path. |
| `session_id_r` | Session blinding factor. |

### 2.4 What the circuit verifies

1. **Verifier token.** `token_sig` is valid under `verifier_key` over the [WIP-110][wip-110] digest of the token claims.
2. **Policy.** `token_method == method`, `assurance_level >= assurance_level_min`, `iat <= now`, `now - iat <= comparison_age_max <= MAX_COMPARISON_AGE`.
3. **Credential image.** At `thumbnail_offset`, `hashes_json` holds the `thumbnail.png` key followed by a hex digest `d` with `R(d) == compared_entry_hash_0`.
4. **Credential claim.** `claims[CLAIM_INDEX] == H_var(CLAIMS_HASH_V1; hashes_json)`, the Poseidon2 sponge the Issuer applies to raw claim bytes.
5. **Challenge.** `compared_entry_hash_2 == challenge_hash`.
6. **Authenticator.** The AAT verifies as in [WIP-106][wip-106] §3.7 with `cdh = request_hash`.
7. **Authorization.** `auth_sig` by `user_pk[pk_index]` is valid over `H_4(DS_WIP_111; request_hash, nonce, aud)`.
8. **Credential validity.** The credential is signed by `cred_pk` for `issuer_schema_id`, is unexpired at `now`, has `cred_genesis_issued_at >= genesis_issued_at_min`, and its subject is derived from `leaf_index`.
9. **Registry.** `user_pk` hashes to the leaf at `leaf_index` under `merkle_root`.
10. **Session.** `session_id` is `0` or the session commitment of `leaf_index` and `session_id_r`.

Constraints 7–10 use the same `leaf_index` witness, so the Authenticator key, the credential and the session all belong to one World ID.
