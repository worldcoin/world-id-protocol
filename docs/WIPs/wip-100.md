## Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [RFC 2119](https://www.ietf.org/rfc/rfc2119.txt).


### Field

Unless otherwise noted, all circuits must use [BabyJubJub](https://docs.iden3.io/publications/pdfs/Baby-Jubjub.pdf a its native field $F$. All arithmetic must be done over $F$. The base field is denoted $F_q$ (or `Fq`) and note that BabyJubJub's base field is BN254's scalar field, but BabyJubJub implements its own scalar field, denoted $F_r$ (or `Fr`).

- $Fq$ has a prime order $p = 21888242871839275222246405745257275088548364400416034343698204186575808495617$
- The $E_M$ BabyJubJub Montgomery elliptic curve defined over $F_q$ has an order $n = 8$ and $\ell = 2736030358979909402780800718157159386076813972158567259200215660948447373041$ is defined as the order of the large prime-order subgroup.

### Hashing

Unless otherwise noted, hashing is done via a Poseidon2 permutation. $P_t$ denotes the Poseidon2 permutation over $F^t$ with the $x^5$ S-box and the round constants specified for BN254.

All hashes defined in the Protocol MUST use **domain separation**. For a domain separator `ds` and inputs $m_1, \dots, m_k$ with $k \le t - 1$: $H_t(ds; m_1, \dots, m_k) := P_t([ds, m_1, \dots, m_k, 0, \dots, 0])[1]$. That is, `ds` occupies the capacity element at state index `0`, the inputs occupy state indices `1..k`, any remaining state elements are zero, and the digest is state element **`1`** of the permutation output.

$H_t$ can be used to denote a Poseidon2 permutation for the stated $t$.

### Signatures

The default signature scheme for the World ID Protocol is an Edwards-curve Digital Signature Algorithm (EdDSA) over the $F_q$ (BabyJubJub).

1. Signatures must follow [RFC-8032](https://datatracker.ietf.org/doc/html/rfc8032) using:
  1. $F_q$ as its finite field;
  2. $E_M$ as its elliptic curve.
  3. The base point $B =\left(5299619240641551281634865583518297030282874472190772894086521144482721001553,16950150798460657717958625567821834550301663161624707787222815936182638968203\right)$.
  3. Poseidon2 as its hash function as defined in [Hashing](#hashing).
2. **Canonical Scalar**. All `s` scalars MUST fulfill $s < \ell$ to prevent signature malleability (i.e. a reduced scalar).
3. **$R$ on curve**. $R$ must be a point satisfying the BabyJubJub curve equation because addition is only complete for on-curve points. The point is NOT REQUIRED to lie in the prime-order subgroup.
4. **Challenge**. $`h = H_8(\texttt{DS\_EDDSA}, R_x, R_y, A_x, A_y, \mathtt{message})`$, so `h` is used as a full-field scalar without reduction.
5. **Cofactored verification equation**. The signature MUST meet the cofactored verification equation. See [Chalkias, K. et al.](https://eprint.iacr.org/2020/1244.pdf).

## Public Key Representation

The `PublicKey` type is introduced to represent public keys of arbitrary elliptic curves. The public key is a structure with two `Field` elements $(x, y)$. Each point MUST be represented with its complete $x$, $y$ coordinates.
