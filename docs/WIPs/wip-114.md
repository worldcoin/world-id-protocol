## 1. Abstract

This spec defines version 2 of the World ID proof request and response. A request has a signed **header**, which OPRF nodes verify, and a **body**, which only the Authenticator and the RP interpret. The body names one proof type, and the spec of that type defines its parameters and its result. New proof types plug in without changing the header, the RP signature or the OPRF nodes.

## 2. Motivation

In version 1, every new proof type adds top-level fields to `ProofRequest` and `ResponseItem`, and validation rules over combinations of those fields. The RP signature covers only `nonce`, `created_at`, `expires_at` and `action`, so fields added for new proof types, such as those of [WIP-202][wip-202], are unsigned.

## 3. Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [RFC 2119](https://www.ietf.org/rfc/rfc2119.txt).

### 3.1 Request

A request is a JSON object with exactly the members `header`, `body` and `signature`.

- The **header** holds what OPRF nodes verify without reading the body.
- The **body** is read only by the Authenticator and the RP. Keeping it out of the header keeps it from the OPRF nodes.
- `body_hash` puts the body under the RP signature ([RP Signature](#32-rp-signature)).

**Encoding:**

- **Field elements:** `0x`-prefixed lowercase hex of their canonical value, less than $q$ ([WIP-100 §3.1][wip-100]).
- **Byte strings:** `0x`-prefixed lowercase hex.
- **Integers:** JSON numbers up to `2^53 - 1`. Larger values, such as `issuer_schema_id`, are decimal strings.
- **Proofs:** their proof type's encoding.

[Appendix A](#appendix-a-examples) has example requests.

**Header:**

| Field | Type | Description |
| --- | --- | --- |
| `version` | integer | `2`. |
| `rp_id` | string | The RP's identifier in the `RpRegistry`. |
| `oprf_key_id` | string, optional | The RP's `OprfKeyId`. Its proof type defines whether it is present. |
| `created_at`, `expires_at` | integer | Unix seconds. |
| `nonce` | Field element | Unique per request; replay protection. |
| `action` | Field element, optional | The OPRF scope the RP authorizes. Its proof type defines whether it is present. |
| `body_hash` | 32 bytes | `SHA-256(JCS(body))`, with JCS per [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785). |

**Body:**

| Field | Type | Description |
| --- | --- | --- |
| `session_id` | string, optional | `"create"` or an existing `"session_"`-prefixed id. Its proof type defines the accepted values. |
| `signal` | byte string, optional | Bytes the proof commits to as `signal_hash = keccak256(signal) >> 8`, or `0` if absent. |
| `credentials` | array | Credentials the RP accepts; see below. |
| `constraints` | object, optional | Which `credential_request_id` combinations satisfy the request, as `ConstraintExpr` in version 1. If absent, all credentials are required. |
| `aat` | object, optional | The RP's [WIP-106][wip-106] AAT requirements; see below. If absent, the Authenticator MUST NOT submit a TAKT or AAT. |
| `proof` | object | `type`, a registered proof type ([Proof Types](#35-proof-types)), and `params`, defined by that type. |

Each `credentials` entry:

| Field | Type | Description |
| --- | --- | --- |
| `credential_request_id` | string | RP-chosen ID of this entry, unique in the request, e.g. `orb`; referenced by `constraints` and the response. |
| `issuer_schema_id` | u64 | As in the `CredentialSchemaIssuerRegistry`. |
| `genesis_issued_at_min` | integer, optional | Minimum `genesis_issued_at`; `0` if absent. |
| `expires_at_min` | integer, optional | Minimum expiration; `created_at` if absent. |

The `aat` object ([WIP-106 §3.6][wip-106-flags]):

| Field | Type | Description |
| --- | --- | --- |
| `required` | boolean | Whether the RP rejects proofs without an AAT. |
| `platforms`, `sec_levels`, `sec_meta`, `authenticator_meta` | arrays of integers, optional | Hints: values the RP accepts. Absent or empty states no requirement. |

The RP MUST enforce its own policy, including accepted Authenticator Providers, on the response's `aat` values ([WIP-106 §4][wip-106-verify]), whether or not the request stated it.

### 3.2 RP Signature

The RP signs with its secp256k1 key, as in version 1; this is not the BabyJubJub scheme of WIP-100. It signs version 1's message ([`compute_rp_signature_msg`](https://github.com/worldcoin/world-id-protocol/blob/main/crates/primitives/src/rp.rs)) with the prefix `0x02` instead of `0x01` and `body_hash` appended:

```
0x02 || nonce || created_at || expires_at || action || body_hash
```

with `nonce` and `action` as 32-byte big-endian, the timestamps as 8-byte big-endian, and `action` omitted when absent.

### 3.3 Response

```json
{ "version": 2, "nonce": "0x…", "session_id": "session_…", "result": { … } }
{ "version": 2, "nonce": "0x…", "error": { "code": "unsupported_proof_type", "message": "…" } }
```

| Field | Description |
| --- | --- |
| `version`, `nonce` | Echo the request's. |
| `session_id` | The session the proof is bound to, if any. |
| `aat` | The AAT's public values: `trust_anchor_key_hash`, `platform`, `sec_level`, `sec_meta` and `authenticator_meta`. Absent if and only if no AAT was used. |
| `result` | The proofs; see below. Absent if and only if `error` is present. |
| `error.code` | One of `invalid_request`, `unsupported_version`, `unsupported_proof_type`, `expired`, `credentials_unavailable`, `aat_unavailable`, `user_rejected`, `generation_failed`. |

**`result`** ([Appendix A](#appendix-a-examples) has an example):

| Field | Description |
| --- | --- |
| `proofs` | One entry per proof, in the order of the `credentials` entries it proves. |
| `proofs[].credential_request_id` | The `credential_request_id` of the `credentials` entry the proof concerns. |
| `proofs[].proof` | The encoded proof, in its proof type's encoding. |
| `proofs[].public` | The proof's public values that the request does not fix, keyed by name. The proof type defines the keys. |
| `attachments` | Optional. Values the RP needs to verify the proofs that are not part of them, keyed by name, e.g. an attestation. The proof type defines the keys. |

### 3.4 Authenticator Processing

The Authenticator MUST reject a request, before any OPRF query or Flamingo request, if:

1. `version` is unknown, or any object has a member this spec or the proof type does not define;
2. `body_hash` does not match `body`;
3. it is expired;
4. `proof.type` is unknown (`unsupported_proof_type`);
5. it violates the rules of its proof type, including an `aat` for a type that does not support AATs.

If `aat` is present, the Authenticator SHOULD use an AAT that meets the hints. If it cannot, it MUST return `aat_unavailable` when `aat.required` is `true`, and otherwise MUST proceed without an AAT.

### 3.5 Proof Types

A proof type's spec MUST define:

1. its `type` name, lowercase snake_case;
2. its `params`;
3. its rules for `header.action` and `header.oprf_key_id`, the accepted `body.session_id` values and AAT support;
4. how many proofs it produces from the credentials `constraints` select, and which `issuer_schema_id`s it supports;
5. its `proofs[].public` keys and `attachments`, and how the RP verifies the proofs against its own request.

An incompatible change to a proof type MUST use a new `type` name. This spec defines `uniqueness` and `session` ([Uniqueness and Session Proof Types](#36-uniqueness-and-session-proof-types)); other specs define further types.

### 3.6 Uniqueness and Session Proof Types

The World ID Uniqueness and Session Proofs ([World ID 4.0](https://github.com/worldcoin/world-id-protocol/blob/main/docs/world-id-4-specs/README.md)), as the types `uniqueness` and `session`.

**Request:**

1. `params` MUST be `{}`.
2. For `uniqueness`, `header.action` MUST be present, with MSB `0x00`, and `body.session_id` MUST be absent or `create`.
3. For `session`, `header.action` MUST be absent, and `body.session_id` MUST be `create` or an existing session.
4. `header.oprf_key_id` MUST be present; both types use the OPRF.
5. `body.aat` MUST be absent. Neither type supports AATs yet.

**Result.** `result.proofs` has one entry per proven credential, and there are no `attachments`. `proof` is the World ID Proof Envelope of [WIP-100 §3.7.2][wip-100]: lowercase hex without a `0x` prefix, with `merkle_root` inside. Its `public` keys:

| Key | Description |
| --- | --- |
| `issuer_schema_id` | Of the proven credential. |
| `nullifier` | `uniqueness` only. |
| `session_nullifier` | `session` only. |
| `expires_at_min` | The value used in the proof. |

See [Appendix A](#appendix-a-examples) for example requests and responses of both types.

## 4. Rationale

1. **Header and body.** Adding a proof type never changes OPRF nodes, since they read only the header.
2. **`action` in the header.** OPRF nodes must check that the scope they evaluate is RP-signed. In the body, they would need the body itself, which reveals the credentials and signal to them.
3. **One proof type per request.** One type with several credentials covers the existing use cases. Combining proof types uses separate requests bound by `session_id`.
4. **AAT requirements in the body.** AATs are meant for every proof type, so the requirements have one place instead of one per type. The values are hints, because a published allowlist would leak the RP's risk policy and the RP may not know all Authenticator Providers in advance.
5. **Fail closed.** Rejecting unknown members stops an Authenticator from ignoring a field the RP relies on.
6. **Common result envelope.** Every proof type returns proofs and the public values the request does not fix, so one shape lets RP tooling parse, log and route results of any type. Verification stays type-specific: the type defines the keys and which circuit checks them.
7. **Signing RPs first.** A contract cannot recompute JCS, so `body_hash` cannot bind the body of a [WIP-101][wip-101] request on-chain. Version 2 therefore requires an RP signature; contract RPs keep version 1, which covers their Uniqueness and Session Proofs, until a later version defines an on-chain-friendly body commitment.

## 5. Security

1. **Signed body.** Unlike version 1, every request field is covered by the RP signature.
2. **Canonicalization.** RP and Authenticator MUST compute `body_hash` over the same JCS serialization. The Authenticator computes it over the `body` it received, not over a re-serialized copy.

## 6. Backwards Compatibility

Version 1 requests remain valid. RPs backed by a [WIP-101][wip-101] contract keep using version 1; version 2 requires an RP signature. Version 1 Authenticators reject version 2 requests as an unsupported version. OPRF nodes MUST accept the version 2 signature message.

## Appendix A. Examples

A `uniqueness` request that accepts an Orb or a document Credential:

```json
{
  "header": {
    "version": 2,
    "rp_id": "rp_…",
    "oprf_key_id": "…",
    "created_at": 1761200000,
    "expires_at": 1761200300,
    "nonce": "0x…",
    "action": "0x00…",
    "body_hash": "0x…"
  },
  "body": {
    "session_id": "create",
    "signal": "0x…",
    "credentials": [
      { "credential_request_id": "orb", "issuer_schema_id": "…", "genesis_issued_at_min": 0, "expires_at_min": 0 },
      { "credential_request_id": "document", "issuer_schema_id": "…" }
    ],
    "constraints": { "any": ["orb", "document"] },
    "proof": { "type": "uniqueness", "params": {} }
  },
  "signature": "0x…"
}
```

A `uniqueness` request for an Orb Credential, with a signal:

```json
{
  "header": {
    "version": 2,
    "rp_id": "rp_00000000001d6bb6",
    "oprf_key_id": "0x…",
    "created_at": 1783446000,
    "expires_at": 1783446300,
    "nonce": "0x…",
    "action": "0x00…",
    "body_hash": "0x…"
  },
  "body": {
    "session_id": "create",
    "signal": "0x…",
    "credentials": [{ "credential_request_id": "orb", "issuer_schema_id": "4242" }],
    "proof": { "type": "uniqueness", "params": {} }
  },
  "signature": "0x…"
}
```

Its response:

```json
{
  "version": 2,
  "nonce": "0x…",
  "session_id": "session_…",
  "result": {
    "proofs": [
      {
        "credential_request_id": "orb",
        "proof": "…",
        "public": { "issuer_schema_id": "4242", "nullifier": "0x…", "expires_at_min": 1783446000 }
      }
    ]
  }
}
```

A `session` request for the session the `uniqueness` response created. It has no `action`:

```json
{
  "header": {
    "version": 2,
    "rp_id": "rp_00000000001d6bb6",
    "oprf_key_id": "0x…",
    "created_at": 1783532400,
    "expires_at": 1783532700,
    "nonce": "0x…",
    "body_hash": "0x…"
  },
  "body": {
    "session_id": "session_…",
    "credentials": [{ "credential_request_id": "orb", "issuer_schema_id": "4242" }],
    "proof": { "type": "session", "params": {} }
  },
  "signature": "0x…"
}
```

Its response:

```json
{
  "version": 2,
  "nonce": "0x…",
  "session_id": "session_…",
  "result": {
    "proofs": [
      {
        "credential_request_id": "orb",
        "proof": "…",
        "public": { "issuer_schema_id": "4242", "session_nullifier": "0x…", "expires_at_min": 1783532400 }
      }
    ]
  }
}
```
