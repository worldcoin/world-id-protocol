## 1. Abstract

This spec defines version 2 of the World ID proof request and response. A request has a signed **header**, which the infrastructure verifies, and a **body**, which only the Authenticator and the RP interpret. The body names one proof type, and the spec of that type defines its parameters and its result. New proof types plug in without changing the header, the RP signature, the OPRF nodes or [WIP-101][wip-101] contracts.

## 2. Motivation

In version 1, every new proof type adds top-level fields to `ProofRequest` and `ResponseItem`, and validation rules over combinations of those fields. The RP signature covers only `nonce`, `created_at`, `expires_at` and `action`, so fields added for new proof types, such as those of [WIP-202][wip-202], are unsigned.

## 3. Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [RFC 2119](https://www.ietf.org/rfc/rfc2119.txt).

### 3.1 Request

A request is a JSON object with exactly the members `header`, `body` and `signature`. `signature` is absent for RPs backed by a [WIP-101][wip-101] contract.

```json
{
  "header": {
    "version": 2,
    "rp_id": "rp_…",
    "oprf_key_id": "…",
    "created_at": 1761200000,
    "expires_at": 1761200300,
    "nonce": "0x…",
    "action": "0x00…",
    "body_hash": "0x…"
  },
  "body": {
    "session_id": "create",
    "signal": "0x…",
    "credentials": [
      { "identifier": "orb", "issuer_schema_id": "…", "genesis_issued_at_min": 0, "expires_at_min": 0 },
      { "identifier": "document", "issuer_schema_id": "…" }
    ],
    "constraints": { "any": ["orb", "document"] },
    "aat": { "required": true, "trust_anchor_key_hashes": ["0x…"], "min_build_version": 0 },
    "proof": { "type": "uniqueness", "params": {} }
  },
  "signature": "0x…"
}
```

Field elements are `0x`-prefixed lowercase hex. Byte strings are `0x`-prefixed lowercase hex. Integers are JSON numbers up to `2^53 - 1`; larger values, such as `issuer_schema_id`, are decimal strings.

### 3.2 Header

The header holds what the infrastructure (OPRF nodes, WIP-101 contracts) verifies without reading the body.

| Field | Type | Description |
| --- | --- | --- |
| `version` | integer | `2`. |
| `rp_id` | string | The RP's identifier in the `RpRegistry`. |
| `oprf_key_id` | string | The RP's `OprfKeyId`. |
| `created_at`, `expires_at` | integer | Unix seconds. |
| `nonce` | Field element | Unique per request; replay protection. |
| `action` | Field element, optional | The OPRF scope the RP authorizes. Its proof type defines whether it is present. |
| `body_hash` | 32 bytes | `SHA-256(JCS(body))`, with JCS per [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785). |

### 3.3 Body

| Field | Type | Description |
| --- | --- | --- |
| `session_id` | string, optional | `"create"` or an existing `"session_"`-prefixed id. Its proof type defines the accepted values. |
| `signal` | byte string, optional | Bytes the proof commits to as `signal_hash = keccak256(signal) >> 8`, or `0` if absent. |
| `credentials` | array | Credentials the RP accepts; see below. |
| `constraints` | object, optional | Which `identifier` combinations satisfy the request, as `ConstraintExpr` in version 1. If absent, all credentials are required. |
| `aat` | object, optional | The RP's [WIP-106][wip-106] AAT requirements; see below. If absent, the Authenticator MUST NOT submit a TAKT or AAT. |
| `proof` | object | `type`, a registered proof type ([Proof Types](#37-proof-types)), and `params`, defined by that type. |

Each `credentials` entry:

| Field | Type | Description |
| --- | --- | --- |
| `identifier` | string | RP-chosen label, unique in the request, referenced by `constraints` and the response. |
| `issuer_schema_id` | u64 | As in the `CredentialSchemaIssuerRegistry`. |
| `genesis_issued_at_min` | integer, optional | Minimum `genesis_issued_at`; `0` if absent. |
| `expires_at_min` | integer, optional | Minimum expiration; `created_at` if absent. |

The `aat` object ([WIP-106 §3.6][wip-106-flags]):

| Field | Type | Description |
| --- | --- | --- |
| `required` | boolean | Whether the RP rejects proofs without an AAT. |
| `trust_anchor_key_hashes` | array of Field elements | Accepted Authenticator Provider keys; MUST NOT be empty. |
| `platforms`, `sec_levels`, `sec_meta`, `authenticator_meta` | arrays of integers, optional | Accepted values. Absent or empty accepts every value. |
| `min_build_version` | integer, optional | Minimum `build_version`; `0` if absent. |

### 3.4 RP Signature

The RP signs, as in version 1 ([`compute_rp_signature_msg`](https://github.com/worldcoin/world-id-protocol/blob/main/crates/primitives/src/rp.rs)):

```
0x02 || nonce || created_at || expires_at || action || body_hash
```

with `nonce` and `action` as 32-byte big-endian, the timestamps as 8-byte big-endian, and `action` omitted when absent.

An RP backed by a WIP-101 contract does not sign. OPRF nodes call its unchanged `verifyRpRequest` with `version`, `nonce`, `created_at`, `expires_at` and `action` (`0` if absent).

### 3.5 Response

```json
{ "version": 2, "nonce": "0x…", "session_id": "session_…", "result": { … } }
{ "version": 2, "nonce": "0x…", "error": { "code": "unsupported_proof_type", "message": "…" } }
```

| Field | Description |
| --- | --- |
| `version`, `nonce` | Echo the request's. |
| `session_id` | The session the proof is bound to, if any. |
| `aat` | The AAT's public values: `trust_anchor_key_hash`, `platform`, `sec_level`, `sec_meta` and `authenticator_meta`. Absent if and only if no AAT was used. |
| `result` | Defined by the proof type. Absent if and only if `error` is present. |
| `error.code` | One of `invalid_request`, `unsupported_version`, `unsupported_proof_type`, `expired`, `credentials_unavailable`, `aat_unavailable`, `user_rejected`, `generation_failed`. |

### 3.6 Authenticator Processing

The Authenticator MUST reject a request, before any OPRF query or Flamingo request, if:

1. `version` is unknown, or any object has a member this spec or the proof type does not define;
2. `body_hash` does not match `body`;
3. it is expired;
4. `proof.type` is unknown (`unsupported_proof_type`);
5. it violates the rules of its proof type, including an `aat` for a type that does not support AATs.

If `aat` is present, the Authenticator MUST use an AAT that meets it. If it cannot, it MUST return `aat_unavailable` when `aat.required` is `true`, and otherwise MUST proceed without an AAT.

### 3.7 Proof Types

A proof type's spec MUST define:

1. its `type` name, lowercase snake_case;
2. its `params`;
3. whether `header.action` is present, the accepted `body.session_id` values, and whether it supports AATs;
4. how many proofs it produces from the credentials `constraints` select, and which `issuer_schema_id`s it supports;
5. its `result`, and how the RP verifies it against its own request.

An incompatible change to a proof type MUST use a new `type` name.

| `type` | `action` | `session_id` | AAT | Proofs | Defined in |
| --- | --- | --- | --- | --- | --- |
| `uniqueness` | required | absent or `create` | not yet | one per selected credential | [§3.8](#38-uniqueness-and-session) |
| `session` | absent | `create` or existing | not yet | one per selected credential | [§3.8](#38-uniqueness-and-session) |
| `embedding_similarity` | absent | absent or existing | supported | exactly one | [WIP-202][wip-202] |

### 3.8 Uniqueness and Session

These are the version 1 Uniqueness and Session Proofs. `params` is `{}`. `uniqueness` requires `action` with MSB `0x00`.

`result` is `{ "responses": [ … ] }`, one item per proven credential:

| Field | Description |
| --- | --- |
| `identifier`, `issuer_schema_id` | Of the proven credential. |
| `proof` | The encoded `ZeroKnowledgeProof`. |
| `nullifier` | `uniqueness` only. |
| `session_nullifier` | `session` only. |
| `expires_at_min` | The value used in the proof. |

## 4. Rationale

1. **Header and body.** OPRF nodes and WIP-101 contracts verify only the header, so adding a proof type never changes them. `body_hash` puts the body under the RP signature. WIP-101 contracts get no `body_hash`: they cannot recompute JCS on-chain.
2. **`action` in the header.** OPRF nodes must check that the scope they evaluate is RP-signed. In the body, they would need the body itself, which reveals the credentials and signal to them.
3. **One proof per request.** Multiple credentials per proof cover the existing use cases. Combining proof types uses separate requests bound by `session_id`.
4. **AAT requirements in the body.** AATs are meant for every proof type, so the requirements have one place instead of one per type. `min_build_version` is only known to the RP, so the request must carry it.
5. **Fail closed.** Rejecting unknown members stops an Authenticator from ignoring a field the RP relies on.

## 5. Security

1. **Signed body.** Unlike version 1, every request field is covered by the RP signature. For WIP-101 contract RPs nothing binds the body at request time; they MUST check the body values, such as `signal` and `issuer_schema_id`, when verifying the proof.
2. **Canonicalization.** RP and Authenticator MUST compute `body_hash` over the same JCS serialization. The Authenticator computes it over the `body` it received, not over a re-serialized copy.

## 6. Backwards Compatibility

Version 1 requests remain valid. Version 1 Authenticators reject version 2 requests as an unsupported version. OPRF nodes MUST accept the version 2 signature message. The WIP-101 interface is unchanged.
