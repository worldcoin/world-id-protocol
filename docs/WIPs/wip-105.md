## 1. Abstract

This spec defines a standard JSON wire format for World ID authenticators to communicate with each other. Messages MUST be JSON-RPC 2.0 objects, and the `method` field MUST use dot-separated `camelCase` segments prefixed with `worldid`. The `params`, `result` and `error` semantics of individual methods are defined by the protocols that use this format.

## 2. Motivation

World ID supports authenticators from different providers and on different platforms. These authenticators need a shared wire format so that application protocols can be implemented independently of a particular transport.

## 3. Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [RFC 2119](https://www.ietf.org/rfc/rfc2119.txt).

### 3.1 JSON-RPC 2.0

Messages exchanged between authenticators MUST be JSON objects conforming to the [JSON-RPC 2.0 specification](https://www.jsonrpc.org/specification).

### 3.2 Methods

The `method` field MUST consist of `camelCase` segments joined by dots `.`. The first segment MUST be `worldid`. For example `worldid.auth.v1.register`.

Specific protocols further restrict the `method`, `params`, `result` and `error` fields.

## 4. Backwards Compatibility

This WIP defines requirements for a new message format. It does not modify existing protocol behavior, contracts or stored data, and implementations that do not exchange authenticator messages are unaffected.
